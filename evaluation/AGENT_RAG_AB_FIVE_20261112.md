# 五题真实 Agent RAG 配对评测

- 日期：2026-11-12
- 模型：`deepseek-v4.1-flash-1017`
- 范围：5 个作者编写的合成缺陷（`case-03`、`case-11`、`case-12`、`case-19`、`case-30`），关闭/开启 RAG 各运行一次；两组共用冻结运行快照、Docker 镜像、提示词实现和任务预算。不是生产缺陷集，也不是统计上充分的重复实验。
- 每题预算：80,000 Token、120 秒、10 次修复尝试；RAG 知识库为 30 条合成类比经验。真实聊天模型、Embedding 服务和 Docker 均参与运行。

## 结果

| 指标 | 关闭 RAG | 开启 RAG |
| --- | ---: | ---: |
| 完整流程成功：待人工审核且 6 条独立测试通过 | 4/5 | 1/5 |
| 最后生成的候选独立测试通过 | 5/5 | 2/5 |
| 实际执行候选测试的任务 | 5/5 | 2/5 |
| 既有测试通过 | 15/15 | 6/15（其余 3 题无候选，未执行） |
| 隐藏验收测试通过 | 15/15 | 6/6（仅对 2 个候选执行） |
| 进入对抗审查节点 | 4/5 | 1/5 |
| 平均任务耗时 | 109.22 秒 | 121.63 秒 |
| P95 任务耗时 | 125.47 秒 | 125.58 秒 |
| 已观测 Token（聊天 + 任务内 Embedding） | 154,303 | 264,411 |

逐题配对主指标为：两组都成功 1 题、仅关闭 RAG 成功 3 题、仅开启 RAG 成功 0 题、两组都失败 1 题；观察到的差值为 -3/5（-60 个百分点），McNemar 精确双侧 `p=0.25`。小样本和每题单次运行不支持统计显著性或普遍效果结论。

关闭 RAG 的流程状态为 4 个 `reviewable`、1 个上游超时。开启 RAG 的状态为 1 个 `reviewable`、2 个超出时间预算、2 个上游超时。RAG 组 5 题均召回 Top-5，共产生 25 条候选案例判断；召回与模型自述适用不等于经验相关性已由人工标签验证。

RAG 组生成的两个候选都通过实际独立测试，但只有 `case-19` 完成验证、对抗审查并进入待人工审核；`case-12` 在对抗审查前遇到模型超时。关闭组 `case-11` 也生成并通过独立测试的候选，但完整流程因对抗审查上游超时而失败。`reviewable` 仅表示等待人工审核，不代表用户接受或已写入知识库。

## 用量和执行审计

`.venv\Scripts\python.exe -X utf8 -m evaluation.isolated_agent_ab score --output work/evaluation/rag-ab-five-20261112-budget80k-retry` 实际完成独立计分；`.venv\Scripts\python.exe -X utf8 -m evaluation.agent_ab_analysis --output work/evaluation/rag-ab-five-20261112-budget80k-retry` 确认 10/10 任务、10/10 基线复现、10/10 容器与工作区清理成功。RAG 任务内使用 4,338 Embedding Token，语料向量化另用 1,771 Token。两个组的 `tokens_complete=false`：上游超时请求没有最终 usage 回执；上述数字只代表可观察用量，未知部分不能按零处理。聊天与 Embedding 费率未配置，费用未知。

本轮所有已观测评测用量约 459,167 Token，尚有超时请求最终用量未知，故不能声称已严格核实总量低于 1,000,000 Token。该汇总包含本次受控审查的 23,418 Token、RAG 配对任务 418,714 Token、语料向量化 1,771 Token，以及先前未完成审查测量已观察到的 15,264 Token。

机器可读计分、逐题状态、Trace、输入快照和清理记录位于忽略目录 `work/evaluation/rag-ab-five-20261112-budget80k-retry/`。配对调度、输入/代码哈希、模型名和预算冻结在其中的 `experiment.json`。

## 结论边界

这次实测没有显示开启 RAG 提升完整修复成功率；观察到的结果是关闭组 4/5、开启组 1/5。开启组还消耗了更多已观测 Token，且更多任务在时间预算内未完成。本轮不能据此认定 RAG 普遍有害：样本只有 5 个作者合成案例、每题单次，模型采样非确定，检索语料也是刻意构造的类比经验。后续若要判断 RAG 收益，需要扩大且独立审核的缺陷集、重复配对运行，并先解决开启 RAG 后更容易触发耗时/超时的链路问题。
