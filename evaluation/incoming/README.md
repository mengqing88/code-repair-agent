## 本次修正与验证方法

- WorkBuddy 的 30 条历史经验代码使用 `target.py`，补丁头却指向 `solution.py`。仅在规范化副本中将补丁头改为 `target.py`，没有修改原始资料、测试断言或修复内容。
- MiniMax 的相关性文件使用 `annotation` 与 `labels` 包装。读取器兼容该格式及直接映射格式，并保留说明，检查所有任务和经验引用是否存在。
- 每题在独立临时目录执行：基线既有测试全通过、验收至少一项真实失败；应用参考补丁后，两组测试全部通过，测试文件哈希保持不变且目标代码发生改变。历史经验同样要求补丁前真实失败、补丁后全部通过。
- 校验器检查任务身份、允许修改范围、报告/契约、经验身份、补丁路径、来源哈希及已审阅样例所用 Python 语法和导入。执行使用 Python isolated mode，关闭 pytest 插件自动加载及缓存。静态检查与临时目录不构成操作系统安全沙箱，不能用来执行任意不可信代码。

## 重跑

在 `F:\项目1` 中运行，输出必须使用尚不存在的新目录：

```powershell
.\.venv\Scripts\python.exe -B evaluation\validate_incoming.py --workers 1 --output evaluation\incoming\normalized-candidate-v2
.\.venv\Scripts\python.exe -B -m pytest evaluation\test_validate_incoming.py -q
```

`--workers` 控制独立样例的并发数；本次可核对的完整通过运行使用 1。`--output` 指定新建产物目录，拒绝覆盖旧记录。退出码 0 表示结构与执行自检通过，1 表示自检断言失败，2 表示配置或执行异常；0 不代表正式评测准入，仍应检查 `formal_eligible`。

## 使用边界与未完成项

只将当前单题的 `sample_repo/<case_id>/` 复制到受限任务工作区；**不要把整个 incoming、oracles、参考补丁、标签或评测报告交给待测 Agent**。读取权限必须由评测运行器限制，不能只依靠提示词。规范化历史经验不会自动导入正式记忆库；知识库语料应在防泄漏审核后独立冻结。

当前 `formal_eligible=false`。后续 `dataset_governance.py` 已核对原始来源字节，按规范化 AST 相似候选与作者相关性关系划成 100 个泄漏组，对任务和经验一起分配开发/验证/测试（126/19/17），并保存不可覆盖的哈希候选快照与 324 条独立审核模板。AST 分组仍需人审，不能当作已确认的语义缺陷家族。尚缺可核验的来源时间/使用权限、独立人工复核、跨组相关性独立标注及代表性；工具参数语义、澄清/拒绝/暂停、恶意输入与故障注入等覆盖也未补全。不能把这些合成类比样例描述为真实 Issue 集，或虚构审核者。

旧 `evaluation/run_benchmark.py` 仍固定读取原 30 题布局，**没有自动接入这里的 162 题**。本次新增的是候选集整理和自检入口；真实 Agent 对照及正式评测接入尚未执行。
