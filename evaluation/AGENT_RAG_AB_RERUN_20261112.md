- 每任务预算为 120 秒、20,000 Token、0.1 元名义费用和 10 次修复尝试，并发 2。模型价格没有配置，费用未知。MCP 与 Cross-Encoder 关闭。
- 30 条作者合成历史经验仅进入 RAG 臂。两臂运行同一冻结代码和配置。与旧 v2 的前后比较不是严格代码因果实验，因为程序文件有变化；v4 内的 RAG 配对才是本轮测量对象。
- Agent 看不到隐藏测试和参考补丁。主指标要求工作流到达 `reviewable` 且真实候选通过 3 条现有与 3 条隐藏测试。没有候选时按失败计，独立测试执行覆盖另行报告。

## 失败归因

本轮修复了 v2 中模型概述日志证据、以及把源码错误地当作位于 `/task` 的问题。真实模型/Docker smoke test 成功复现 case-11；完整 60 题中 57 题确认原缺陷复现，审计逐项核实了引用是 stdout 或 stderr 中的原文。

之后主要遇到两类阻塞：

1. Token 输入预检在请求发送前拒绝过长输入。关闭组 19/30、开启组 21/30 分类为 `token_budget_exceeded`。该实现把序列化输入字节当作保守 Token 上界，因而有些任务在账面 Token 尚有剩余时仍被拒绝；RAG 上下文增加了输入长度。
2. 生成的回归测试有时返回完整 `test_*` 函数，而生产代码又将它包进 `test_reported_defect()`。内层函数只被定义，没有执行断言；pytest 因而报告旧代码通过，正确的基线门禁拒绝继续。关闭组 9 题、开启组 7 题出现该结构。

此外，每组各有 1 个超时；关闭组有 1 个空模型回复，开启组有 1 个不完整模型回复。没有补丁验证或对抗审查到达。关闭组观察到 16 次成功的补丁模型响应、20 次工具调用，但仍没有最终候选；开启组虽然进入补丁代理节点，却在收到首次成功的补丁模型响应前因预算/超时停止。失败分组和逐题结果见 JSON。

## 用量与限制

两组任务共观测 489,368 个模型及 Embedding Token；另加语料建立的 1,771 Token。费用因未配置单价而未知。平均耗时虽低于每任务 120 秒，但有包含收尾在内的任务记录超过该值（最高关闭组 123.67 秒、开启组 126.52 秒），所以不能声称严格的端到端墙钟硬上限。

评测数据是小规模合成任务、作者编写的类比经验，每组单次运行；模型使用提供方默认生成参数。此结果不能推断真实仓库效果，也不能证明 RAG 无效或有效。目标 16/30→22/30 与回归 96% 均未达成/测得。
