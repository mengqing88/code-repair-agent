- 生产入口：`adversarial_review.review_patch`，实际调用兼容 API；不是模拟回复。
- 范围：4 个作者编写的合成补丁，每个计划重复 2 次。预期标签尚未由独立审查者复核。

评测入口为 `evaluation/run_adversarial_review_quality.py`，样例位于 `evaluation/adversarial_review_cases_20261112.json`。预检命令 `.venv\Scripts\python.exe -m evaluation.run_adversarial_review_quality --dry-run` 实际通过：4 个补丁均在独立副本内成功应用，静态审查均未提前拦截，模型调用数为 0。初始评测脚手架因没有 pytest 收集目标而被测试保护机制拒绝；补齐固定收集目标并把临时副本移出仓库后，预检通过。

操作说明：首版脚手架没有重定向 pytest 收集器内部 `tempfile.TemporaryFile` 的系统临时目录；预检时这些临时文件短暂写入 Windows 默认 C 盘 Temp，随后由上下文自动删除。后续脚本已将 `TMPDIR`、`TEMP`、`TMP` 和 Python `tempfile` 目录统一设为 `F:\CodexTemp\repair-review-quality`，所有后续预检和评测临时文件只使用 F 盘。首版预检还曾把受保护读取结果与原始源码逐字比较；改为核对隔离副本中的文件内容后，4 个补丁预检全部通过。

总覆盖率为 **2/8**。两个已完成审查的整体结论均符合预期；它们都针对同一类边界回归，因此不能把 2/2 解读成总体准确率。已观察到的误放行为 0；安全补丁没有得到完整判断，误拒率未知；兼容性和权限风险类别没有结果。

两次完整审查都返回三项检查，共 6 条引用。生产审查器已在生成结果前校验引用，离线复核也在统一 LF/CRLF 行尾后确认 **6/6** 引用都来自基线或补丁源码。首版离线统计没有归一化 Windows 换行，把它们误记为无效；评测脚本已修正。

评测直接调用审查器，没有先运行或附上 pytest 验证结果；两次完整响应中模型都看到 `validation=null`。真实工作流通常在测试节点之后再进入审查，因此本次结论不等同于完整工作流上下文下的质量验收。

## 预算与异常

- 总时限：120 秒；达到预算上限后停止。
- Token 上限：20,000；观察到的用量为 12,654 Token。另一个超时请求没有返回 usage，真实用量可能高于已观察值。
- 聊天费率未配置，无法估算人民币费用；0.10 元费用上限未启用。用户已确认本次接受费用未知并按 Token 上限继续。
- 共启动 5 次模型请求尝试：2 次不完整响应、2 次完整响应、1 次上游超时。

## 结论边界

本次只证明模型在两个边界回归样例上给出了正确拒绝，并提供了可验证源码引用。当前服务出现不完整响应和超时，导致安全补丁、兼容性回归和权限风险审查没有完成。生产审查器对不完整回复会停止并 fail-closed，但这不等于审查质量通过。

该小型样例集由作者编写，不能估算真实误放行率、误拒绝率，也不能代表复杂仓库或生产分布。直接审查评测没有运行 pytest，模型输入中的 `validation` 为 null；它测量的是缺少测试结果证据时的独立审查行为，不等同于生产工作流在测试节点之后的审查表现。后续质量结论还需要补齐 fee rate、处理服务端不完整响应/超时，并在完整覆盖所有类别及真实测试上下文后重复评测；不同模型或提示词的对比必须另开并记录独立预算。

归档摘要见 [机器可读结果](REAL_MODEL_REVIEW_QUALITY_20261112.json)。原始逐次输出位于忽略目录 `work/evaluation/real-model-review-quality-20261112-retry1.json`。首轮脚手架失败和修复过程没有模型请求；它们不计入模型质量结果。

## 受控补测：附带真实有限测试结果

初测未覆盖完整类别，因此追加一次独立补测，不覆盖或合并初测数据。补测在每个候选补丁上实际运行了有限 pytest fixture，并把通过结果传给同一个生产 `review_patch` 审查器；每题重复两次，四类各两次，共 8 次真实模型审查。四个 fixture 均通过，但三个负例的测试刻意没有覆盖契约中的缺陷（边界 120、整数 0、非所有者管理员），用来检验审查器能否从源码和报告中发现“有限测试通过、实际行为仍错误”的情况。

| 类别 | 正确判断 | 观察到的行为 |
| --- | ---: | --- |
| 安全补丁：总数为 0 时返回 0 | 2/2 | 均批准 |
| 边界回归：上界 120 被改为开区间 | 2/2 | 均拒绝并识别边界问题 |
| 兼容性回归：把有效整数 0 当成缺省值 | 2/2 | 均拒绝并识别兼容性问题 |
| 权限回归：让管理员绕过 owner-only 规则 | 2/2 | 均拒绝并识别权限风险 |

8/8 次审查完整结束，样例预期判断 8/8 正确，6/6 个错误补丁均识别目标风险；本次样例观察到的误放行和误拒绝均为 0。生产审查器返回的源码引用全部经评测脚本与真实基线或补丁源码逐字核对，8/8 有效。模型与上下文 usage 均完整，实际观察到 23,418 Token，平均每次 24.41 秒、P95 36.475 秒；8 个隔离工作区均完成清理。机器可读摘要为 [受控补测结果](REAL_MODEL_REVIEW_QUALITY_CONTROLLED_20261112.json)，原始逐次结果保留在忽略目录 `work/evaluation/review-quality-controlled-20261112.json`。

这项补测比初测更接近生产节点顺序，因为模型实际获得了 pytest 通过证据；同时它也只验证小型合成夹具。标签由作者制定而非独立专家审核，只有 2 个安全样例和 6 个负例，不能推算生产误放率、误拒率或复杂代码审查质量。应表述为“真实模型在 4 类合成补丁、每类重复 2 次的受控样例中判断 8/8 符合预期，且引用均可追溯”，不能写成生产审查质量已被证明可靠。
