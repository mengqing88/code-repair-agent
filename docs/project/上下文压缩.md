# 修复 Agent 的上下文压缩

模型的**单次上下文窗口**和任务的**累计 Token 预算**是两项限制。前者要求本次输入与预留输出放得下，后者约束整个任务已经消耗和准备消耗的用量。压缩只能减少后续请求携带的历史，不会返还已经消耗的 Token、费用、时间或工具次数。

## 发送前的数据流

`repair_workflow` 保留本轮原始 ReAct 历史；普通模型请求和工具模型请求都在 `llm_client` 发送前，先沿用输入脱敏，再通过 `context_compression.fit_request_context` 构造发送视图，随后执行原有任务预算与费用预检。不会用摘要覆盖原始对话、任务状态、Observation 档案或已有 Trace。既有工具输出的约 20,000 字符预览限制仍然存在，本次摘要不能找回此前已裁掉的内容。

Token 估算包含完整输入、模型规则、工具定义和输出 JSON Schema，沿用 `tiktoken`、20% 余量及 512 Token 封装余量；没有 tokenizer 时退回 UTF-8 字节估算。估算不等于供应商精确计费分词，因此还需要处理供应商实际拒绝。

输入估算没有超过 `窗口 − 输出预留` 时保留原文；超过时，优先保留最近两个完整工具交换，将较早交换换成本地生成的结构化摘录。若仍放不下，可逐步缩减摘录并连同最近交换一起压缩。一个交换中的 reasoning、并行 `function_call` 和全部对应 `function_call_output` 一起保留或一起移除，不把调用和结果拆开。缺结果、孤立结果或重复调用标识直接报 `context_history_invalid`，不发送损坏历史。

所有原始 user/system/developer 消息、顶层规则、工具 Schema 和输出契约完整保留，原有用户补充消息的先后顺序也不改变。最终输入加输出上限必须在配置窗口内；单次输出同时受原有 40,960 上限、任务剩余 Token 与可用费用限制。初始任务或 Schema 自身过大、摘要包络无法满足配置上限时，报 `context_window_exceeded`，要求缩小输入/工具清单或核对真实容量，不将它误标成任务 Token 预算耗尽。

最终 JSON/Schema 纠错也复用这条链路：`repair_workflow` 将原任务及本次校验错误、完整旧候选分别保存为不可裁剪的 user 消息，将已执行工具的 Observation 逐条标记为可压缩参考消息。这个内部标记只用于压缩分组，发送前会从消息顶层移除；正文仍把 Observation 明确标成参考数据。`ask_model_with_usage` 兼容原字符串，也支持这类消息列表，因此旧 Observation 可以压缩，候选 diff 不会被摘要替换。纠错请求不携带工具定义，不执行新的工具；压缩条目保留工具名、观察序号、参数和结果哈希，不将观察序号冒充真实工具调用 ID。

## 源码太多时的语义总结（2026-11-18）

上述 ReAct 历史压缩仍是本地确定性摘录。新增的 `source_context.py` 单独处理**相关源码太多**的情况，会额外调用同一个聊天模型生成导航摘要，不把两种压缩混为一谈。

补丁初始输入中的 `code_text`/`code_evidence` 去重后，或 ReAct 的单次 `read_code` 返回超过 **16,000 字符**，就构造源码发送视图。这个阈值是源码的固定预留额度，不代表实际模型窗口已满；完整请求仍由共同客户端检查窗口与任务预算。按最多 **60 行/4,000 字符**分块，以缺陷报告、复现线索中的标识符/文本匹配作确定性排序；保留最相关的两块原文（合计最多 **8,000 字符**），对接下来最多四块生成摘要，其余仅报告省略范围与数量。它不是 AST/依赖图分析，也不声称找到了所有相关代码；超长单行只保留前 4,000 字符并显式标记截断。

模型只返回 `chunk_id` 和摘要正文；服务端要求本批 ID 完整、唯一、无额外字段，随后用原分块绑定路径、起止行和 SHA-256，拒绝伪造 ID、缺项及自填来源。哈希针对脱敏并统一 LF 换行后的源码块，`read_code` 返回的 `content_sha256` 使用同一口径，避免 Windows CRLF 与粘贴 LF 误报变化。该校验证明摘要对应哪个输入块，**不能证明模型每句话都符合源码**。提示词要求依赖摘要修改代码前先按行回查，最终仍需原文、固定测试与独立审查；当前没有证明模型一定遵守回查要求的服务端语义判定器。

每次 `llm_propose_patch`（一次候选生成）最多 **4 次逻辑摘要请求**，包含初始源码和工具返回的摘要；单次最多处理四块、最多 **512 输出 Token**，不做摘要 Schema 纠错重生成，底层瞬时网络故障仍按既有策略有界重试。调用共享原任务的时间、Token、费用、审计与未知用量处理；不会创建一份重置后的任务预算。摘要前用 UTF-8 字节保守估算输入、预留 4,096 Token 给后续流程；剩余 Token 不足或时间少于 10 秒时跳过摘要。SDK 仍按实际配置窗口、剩余 Token 与价格再次限制发送。阈值与上限属于源码常量，随执行清单源码身份冻结；不是新增环境配置。

无效 JSON、无效来源或普通模型故障会降级为保留的原文摘录和明确省略记录，已返回的实际用量仍累计；未知结果、预算耗尽、审计写入失败继续上抛，不当成摘要优化失败悄悄忽略。达到四次上限后直接摘录，不另请模型。原任务源码、证据与工具执行档案保持原样，仅替换送给模型的视图，也不将摘要作为验证通过的依据。

复现准备另有一次大仓库入口：源码收集上限从 100,000 调为 **1,000,000 字符**；超过原 100,000 字符时复用上述选择/摘要器，完整副本继续留在隔离目录，模型只收到有界视图。复现阶段没有 ReAct 原文回查工具，缺少必要信息时应澄清；摘要不能代替实际复现证据。超过新收集上限仍明确要求缩小范围，并非支持无界仓库。

新增 Trace 事件 `source.summary`、`repair.source_context` 和 `source.tool_context` 记录生成/失败/预算跳过状态、摘要数与省略数，真实模型请求与用量继续走原发送和计量链路。源码摘要发生在工具约 20,000 字符预览之前；以前已被预览裁掉的历史内容仍不能凭摘要恢复。

## ReAct 历史摘录是什么

ReAct 历史压缩是**本地确定性摘录**，不是额外调用模型生成的语义摘要。工具条目包括调用标识、工具名、参数/结果的 SHA-256、首尾片段；模型消息保留内容片段和来源哈希；同时记录交换数、工具调用数和省略条目数。被截断内容明确标注“不是完整源码或完整补丁”，被省略条目也不能理解成没有执行过。

不额外请求摘要模型，可以减少摘要阶段的费用、故障和编造内容；代价是无法保证保留所有中间细节或语义结论。需要缺失证据时，Agent 可以使用已获准的只读工具重新读取。这可能增加后续读取次数，仍受原来的权限、无进展检测和工具预算约束。摘要不能作为外部写操作未执行的证明，审批、幂等和未知结果处理仍以服务端持久记录为准。

每次从原历史重新构造视图，避免“摘要再摘要”逐轮失真；不将截断片段当成可应用 diff，也不通过压缩重新执行任何工具。原有审计存储和脱敏规则不因此改变，本文不承诺旧 Trace 中原本已裁剪的内容可完整恢复。

## 供应商拒绝与重试

只针对 HTTP 400/413/422 中明确的上下文过长代码或消息，允许一次更强压缩，并将输出上限进一步缩至预留额度。普通参数错误不走这条重试。若输入和输出都无法继续缩小，不重复发送相同请求；第二次仍被拒绝就停止并报结构化窗口错误。

这一次纠正只重发模型请求，不重跑 ReAct 工具执行。外层瞬时网络故障重试也不能重置上下文纠正次数；纠正共享该次请求的时间额度，并继续检查原任务剩余时间和预算。明确被拒绝的请求不作为成功响应计量；实际响应的 usage 沿用原有持久计量。供应商若在错误中不返回计费信息，项目无法凭空得知该错误的实际费用，也不保证错误请求免费。

## 配置与生效

非敏感模板见 [context.env.example](../../deploy/context.env.example)。默认值和约束：

| 配置 | 默认值 | 作用与范围 |
| --- | --- | --- |
| `CHAT_CONTEXT_WINDOW_TOKENS` | 128000 | 实际模型容量，允许 2048–2000000；默认值不是自动探测 |
| `CHAT_CONTEXT_OUTPUT_RESERVE_TOKENS` | `min(8192, window/4)` | 触发压缩时预留的最少输出空间，允许 128–窗口的一半；不是普通请求固定输出上限 |
| `CHAT_CONTEXT_KEEP_TOOL_ROUNDS` | 2 | 优先原样保留的最近完整交换数，允许 0–8；不是无条件保留承诺 |
| `CHAT_CONTEXT_SUMMARY_TOKENS` | `min(2048, window/8)` | 所有生成摘要合计的估算上限，允许 64–窗口的一半；设得过小可能连必要包络也放不下而拒绝请求 |

四项配置纳入执行清单，冻结任务不因后续进程环境变化漂移。默认参数生效于新启动进程；本轮未改本机 `.env`，也未重启现有服务。源码更新会触发旧冻结任务的环境身份校验；旧任务需要原环境，不能跳过校验强行续跑。

Trace 的 `model.context` 记录压缩前后估算、窗口、保留交换数、摘要来源哈希及强制压缩标志；`model.request prepared` 记录实际发送视图；`provider_rejected` 记录是否进入一次纠正。完整任务 Token 用量仍以真实响应与原有未知用量记录为准。
